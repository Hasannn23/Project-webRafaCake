# PENGUJIAN BLACK BOX — SISTEM RAFA CAKE

Dokumen ini berisi daftar skenario pengujian Black Box untuk **Sistem Informasi Rafa Cake** guna memastikan seluruh fitur utama (Autentikasi, Manajemen Profil, Katalog Produk, Pemesanan, Kelola Ulasan, serta Dashboard Admin) berfungsi sesuai ekspektasi.

| ID Tes | Fitur yang Diuji | Skenario / Deskripsi Input | Kriteria Keberhasilan (Ekspektasi Sistem) |
|---|---|---|---|
| **BB-01** | Registrasi Akun Pelanggan | Mengisi form registrasi dengan data valid (Nama: "Andi", Email: "andi@test.com", Password: "password123", Konfirmasi Password: "password123") lalu klik tombol "Register". | Akun berhasil dibuat, sistem mengalihkan pengguna ke halaman dashboard/verifikasi email, dan data tersimpan di database. |
| **BB-02** | Registrasi Akun Pelanggan | Mengisi form registrasi dengan email yang sudah terdaftar di sistem (misal: "admin@rafacake.com"), password "password123", konfirmasi password "password123". | Registrasi gagal, sistem menampilkan pesan kesalahan *"The email has already been taken"* di dekat field email. |
| **BB-03** | Registrasi Akun Pelanggan | Mengisi form registrasi dengan password yang kurang dari 8 karakter (misal: "123"). | Registrasi gagal, sistem menampilkan pesan validasi *"The password must be at least 8 characters."* |
| **BB-04** | Registrasi Akun Pelanggan | Mengosongkan seluruh kolom input pada form registrasi lalu langsung mengeklik tombol "Register". | Registrasi ditolak oleh sistem dan muncul pesan peringatan bahwa kolom input wajib diisi (*required*). |
| **BB-05** | Login Pelanggan | Memasukkan email pelanggan terdaftar ("andi@test.com") dan password yang benar ("password123") pada form login, lalu klik "Log in". | Pengguna berhasil masuk ke sistem dan langsung diarahkan kembali ke halaman utama/katalog produk dengan menu akun aktif. |
| **BB-06** | Login Admin | Memasukkan email admin ("admin@rafacake.com") dan password yang benar pada form login, lalu klik "Log in". | Admin berhasil login dan diarahkan secara otomatis ke halaman **Dashboard Admin**. |
| **BB-07** | Login Akun | Memasukkan email terdaftar namun dengan password yang salah/keliru, lalu klik "Log in". | Login gagal, sistem menampilkan pesan error *"These credentials do not match our records."* |
| **BB-08** | Login Akun | Memasukkan email yang belum terdaftar di sistem beserta password apa saja, lalu klik "Log in". | Login gagal dan menampilkan pesan kesalahan kredensial tidak terdaftar. |
| **BB-09** | Logout Akun | Mengklik tombol "Log Out" di menu navigasi akun saat sedang dalam kondisi login. | Sesi login dihapus, pengguna berhasil keluar dari sistem, dan diarahkan kembali ke halaman login/utama. |
| **BB-10** | Lupa Password | Memasukkan email terdaftar ("andi@test.com") pada halaman Lupa Password lalu mengeklik tombol "Email Password Reset Link". | Sistem memproses pengiriman dan memunculkan notifikasi sukses bahwa tautan reset password telah dikirim ke email tersebut. |
| **BB-11** | Lupa Password | Memasukkan email yang tidak terdaftar di sistem pada halaman Lupa Password lalu mengklik kirim link reset. | Permintaan ditolak dan sistem menampilkan pesan error *"We can't find a user with that email address."* |
| **BB-12** | Kelola Profil (Update Data) | Mengubah data nama menjadi "Andi Baru" dan email menjadi "andibaru@test.com" di halaman Profile, lalu klik "Save". | Data profil diperbarui di database dan sistem menampilkan status pesan sukses *"Profile updated successfully"*. |
| **BB-13** | Kelola Profil (Update Password) | Memasukkan password saat ini dengan benar, lalu mengisi password baru "newpassword123" beserta konfirmasinya, lalu klik "Save". | Password berhasil diganti, data ter-update di database, dan sistem menampilkan status sukses. |
| **BB-14** | Kelola Profil (Hapus Akun) | Memasukkan password saat ini pada bagian "Delete Account" lalu mengklik tombol merah konfirmasi hapus akun. | Akun pengguna dihapus secara permanen dari database, sesi login langsung berakhir, dan pengguna diarahkan ke halaman utama. |
| **BB-15** | Pemesanan Kue | Memilih salah satu kue di katalog, mengisi form pesanan dengan kuantitas valid (misal: 1), alamat lengkap, tanggal pengiriman, lalu klik "Pesan Sekarang". | Pesanan diproses, data tersimpan di database (tabel `orders`) dengan status awal "pending", dan user diarahkan ke dashboard pemesanan mereka. |
| **BB-16** | Pemesanan Kue | Mengisi kuantitas pesanan dengan angka negatif atau nol (misal: -2 atau 0) lalu mengeklik tombol "Pesan Sekarang". | Pemesanan ditolak oleh sistem dan muncul pesan kesalahan/validasi bahwa kuantitas pesanan minimal harus bernilai 1. |
| **BB-17** | Kelola Ulasan (Tambah Review) | Memilih pesanan dengan status selesai di dashboard user, memberi rating bintang 5, menulis deskripsi "Kue sangat enak!", lalu klik "Kirim Ulasan". | Ulasan berhasil disimpan ke database (tabel `reviews`), berasosiasi dengan order tersebut, dan tampil di daftar ulasan produk terkait. |
| **BB-18** | Kelola Ulasan (Edit Review) | Mengklik tombol edit pada ulasan milik sendiri, memperbarui konten teks ulasan, lalu mengeklik tombol "Update". | Ulasan berhasil diperbarui di database dan tampilan teks ulasan pada produk langsung berubah. |
| **BB-19** | Kelola Ulasan (Hapus Review) | Mengklik tombol hapus/delete pada ulasan milik sendiri yang sudah dipublikasikan. | Ulasan berhasil dihapus dari database dan tidak lagi ditampilkan di halaman review produk. |
| **BB-20** | Kelola Ulasan (Hapus oleh Admin) | Admin mengakses menu ulasan di dashboard admin, mencari ulasan tidak pantas, lalu mengklik tombol "Hapus". | Ulasan yang dipilih berhasil dihapus secara permanen dari sistem oleh admin. |
| **BB-21** | Kelola Produk - Admin (Tambah) | Admin mengisi form produk baru (Nama: "Black Forest", Kategori: "Kue Ultah", Harga: "180000", Deskripsi, file gambar valid), lalu klik "Simpan". | Produk baru tersimpan di database dan langsung tampil di daftar produk admin serta katalog publik. |
| **BB-22** | Kelola Produk - Admin (Validasi Gambar) | Admin membuat produk baru tetapi mengosongkan unggahan file gambar produk, lalu klik "Simpan". | Sistem menolak penyimpanan dan menampilkan validasi error *"Gambar produk wajib diunggah."* |
| **BB-23** | Kelola Produk - Admin (Edit) | Admin memilih salah satu produk, mengubah harganya dari "180000" menjadi "190000", lalu mengeklik tombol "Update". | Perubahan harga produk berhasil disimpan di database dan harga baru langsung ter-update di katalog publik. |
| **BB-24** | Kelola Produk - Admin (Hapus) | Admin mengklik tombol hapus/delete pada salah satu produk di daftar produk admin. | Produk berhasil dihapus dari database dan otomatis hilang dari daftar produk admin serta katalog publik. |
| **BB-25** | Kelola Produk - Admin (Toggle Status) | Admin mengklik tombol toggle/saklar status aktif/nonaktif pada salah satu produk di daftar produk. | Status produk berubah (misal menjadi tidak aktif), sehingga produk tersebut tidak lagi muncul di halaman katalog yang diakses oleh pelanggan. |
| **BB-26** | Kelola Kategori - Admin (Tambah) | Admin mengisi nama kategori baru "Kue Basah" pada form kelola kategori lalu klik "Simpan". | Kategori baru berhasil disimpan dan muncul di pilihan dropdown kategori saat admin menambah/mengedit produk. |
| **BB-27** | Kelola Kategori - Admin (Edit) | Admin mengubah nama kategori "Kue Basah" menjadi "Jajanan Pasar", lalu mengeklik tombol "Update". | Nama kategori berhasil diperbarui dan semua produk yang terhubung dengan kategori tersebut ikut ter-update. |
| **BB-28** | Kelola Kategori - Admin (Hapus) | Admin mengeklik tombol hapus/delete pada kategori "Jajanan Pasar". | Kategori terhapus dari sistem, dan produk terkait disesuaikan agar tidak mengalami error (misal status kategori menjadi kosong/uncategorized). |
| **BB-29** | Kelola Pemesanan - Admin (Status) | Admin membuka menu daftar pesanan masuk, lalu mengubah status pesanan pelanggan tertentu dari "pending" ke "proses" atau "selesai". | Status pesanan di database diperbarui dan perubahan tersebut langsung ter-update di riwayat pesanan milik pelanggan. |
| **BB-30** | Kelola Pengguna - Admin (Hapus User) | Admin mengakses menu kelola pengguna, lalu mengeklik tombol hapus pada salah satu akun pelanggan terdaftar. | Akun pelanggan tersebut dihapus dari database, sesi login mereka terputus jika sedang aktif, dan mereka tidak dapat login kembali. |
